# amergin-example-data

Benchmark data and report for [`wilhelmi-lab/amergin-example`](https://github.com/wilhelmi-lab/amergin-example).

This repo is written to by amergin-example's CI after every successful
`amergin run`. Each run lands in its own directory under
`{source_hash}/{machine_id}/{timestamp}/` so multiple machines and
multiple re-runs of the same source coexist without overwriting.

The aggregated report lives at the top-level `report/` directory and is
served via GitHub Pages:

→ <https://wilhelmi-lab.github.io/amergin-example-data/report/>

## Layout

```
{source_hash}/                   # 12-char commit prefix or `<head>-dirty-<diff>`
  {machine_id}/                  # AMERGIN_MACHINE_LABEL or 16-char fingerprint hash
    {timestamp}/                 # ISO-8601 UTC, e.g. 2026-05-26T14-05-15Z
      meta.json                  # source/machine/timestamp + amergin version
      system_fingerprint.json    # cpu / os / gpu detected at run time
      summary.json               # aggregated metrics (medians, p95, atol)
      inputs/                    # *.npz: arrays generated by @input_generator
      outputs/                   # *.npz: each backend's result
      timings/                   # *.json: raw iteration_ms lists
      verify/results.json        # per-backend pass / atol_max

report/                          # aggregated across every run on disk
  index.html
  badge.json
  benchmark-action.json
  *.png
```

## Filtering what shows up on the report

Two layers, configured in `amergin-example`'s `pyproject.toml`:

```toml
[tool.amergin.history]
ignore_before = "2026-01-01"           # ISO-8601 cutoff
machines = ["nvidia-a100", "mac-m3"]   # whitelist by machine_id
```

The data on disk is never deleted by these filters — they only hide
runs from the report. Interactive filters on the page work on top of
the same data and can re-include filtered-out runs at view time.
